# Public Contract v1: frontend handoff

`v1-examples.json` contains SYNTHETIC DEVELOPMENT EXAMPLES, never real legal or model findings. `v1-example.json` preserves the original handoff's singular path as one labelled completed result example. These files and `openapi.json` are generated by `python -m apps.api.scripts.export_contracts`. The original four role files remain the baseline. These explicit additive fields/decisions are published for FE1/FE2/BE2 review; no teammate implementation exists in this clone.

- All routes use `/api/v1`. All document routes after upload require `X-Session-Token`. Wrong/missing tokens and unknown documents share 404 NOT_FOUND.
- PATCH with empty corrections and confirmed language/type records review. No genuine change means revision unchanged; real text/type/language changes increment once, confirm that revision, and invalidate old findings. `reviewed_revision` is explicit in metadata/extraction/PATCH responses. Edits during queued/running analysis return 409.
- All errors, including request validation, use `{error:{code,message,retryable},request_id}`. Validation messages omit input values.
- Optional extraction `progress` uses real completed/total page or block counts. Analysis `progress` retains `completed_clauses,total_clauses` plus optional `stage,failed_clauses`.
- Partial means status `running` or terminal `needs_review`, not a new status enum. Available validated partial results are retained. Terminal results enumerate every unanalysed clause ID through `failed_clauses` (optional additive result/progress field); generic warnings alone cannot account for missing clauses. Coverage must remain honest.
- Metadata has `expires_at` (UTC ISO timestamp) and `reviewed_revision`; aggregate pending/exhausted cleanup appears in health. Polling GETs do NOT extend expiry; authenticated PATCH/analysis/question/source actions do. Background work does not extend it. Expiry tombstones and cancels work like deletion. There is no invented countdown/reset endpoint.
- Health: `status`, `mode`, `extraction:{ready,pdf,docx,ocr:{available,languages}}`, `ml:{available,classifier_ready,generator_ready,language_paths}`. Unknown readiness is null; language_paths entries identify input/output and tested/experimental/unsupported/unknown. Fixture mode explicitly reports simulation, never real readiness.
- Health extraction additionally reports `isolation:{mode:"subprocess",timeout_seconds,memory_mb}`. OCR language availability means local engine/assets present, not general extraction accuracy. All OCR needs review; Punjabi has a recorded synthetic word-level error. `EXTRACTION_TIMEOUT` is a retryable 504 parser failure, separate from `MODEL_TIMEOUT`.
- Real ML is default. `ML_MODE=fixture` is explicit development-only literal-echo simulation; warnings/provenance mark every result and answer. Real failure never switches mode.
- BE1 supplies analysis ID; private start returns 202 with that same ID. Private service credential proposal: `X-ML-Service-Token` (BE2 confirmation pending). Private QuestionRequest includes document_id, document_revision, analysis_id, question, output_language, client_request_id and reviewed clauses. No public session token is forwarded. Answer reference IDs must already exist in analysis references.
- DELETE immediately hides document; private cleanup may be pending. Private DELETE retries up to 5 times with bounded backoff, stores IDs only, and exposes aggregate unresolved cleanup counts in health. A downstream failure is never reported as confirmed erasure. Restart loses in-memory retry work; BE2 expiry is required.
- Source uses no-store and authenticated attachment download; no static runtime mount. Browser token persistence is not supported.
- Official legal aid is a static reviewed allowlist; no external document/AI requests. Official-reference URL trust is checked at the adapter boundary but curation remains BE2's responsibility.

Suggested frontend sequence: POST upload → GET metadata until extraction_ready → GET extraction → PATCH confirm/correct → POST analyses → GET analysis until terminal → GET source / POST questions → DELETE. No export endpoint is needed.
